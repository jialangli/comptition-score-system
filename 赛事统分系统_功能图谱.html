第一部分 · 裁判端7 个功能域

登录与鉴权（裁判码）

wireframe P1 / P1.5 / P1.6 / P1.5b / P1.5c

码由主办方 / 主控赛前建档，6 位无歧义字符；换赛事须重新发码，旧码在新赛事无效。

「断网可登录」的前提是首登联网激活过 —— 没激活过的码只能在联网状态用。

比赛主屏（赛台队列）

wireframe P2 / P2e / P2e2 / P2f / P2g

顺序不对由后台「赛台与赛程」调整分台顺位，平板不提供调整入口。

长选手名折叠为「秦朗 等 4 人」（> 2 人折叠）并给 title 全量，避免撑破面板与表格。

打分表（单队 · 三赛项）

wireframe P3 / P4 / P5 / P5.5 / P3g

评分方式只有 count / toggle（下拉只有计数器 / 开关），数值分与等级分已收敛掉。

提交确认弹窗是「汇总级防呆」，与逐项签名分工：签名认每一分，弹窗认整场。

双侧计分板与记牌

wireframe P5.6 / P5.6g / P5.7 / P5.7b / P5.8c / P5.8d / P5.9

红牌与裁定的「取消资格」是两条链：红牌保留成绩、榜内名次 0；裁定是整行剔除、不进榜单。

双队选手代表都要签字（A / B 各一 + 裁判），缺一不可提交 —— 这是整场提交的硬闸。

争议 / 申诉上报

wireframe P5.10 → 裁判长 P8 家族

取代「口头喊裁判长」：工单号进队列，裁判长在执裁页签就能看到待裁定徽标。

选手 / 教练不直传照片，由裁判端拍摄上传，并随工单登记。

改分申请（改分模式）

wireframe P2b / P2b-改时 / P2c / P2d

已生效成绩的修改一律走「申请 → 审批」，改分申请不改变名次，审批通过后才重算。

同一队伍同一轮只允许存在一张待审批申请，避免重复申请把分数改乱。

离线暂存与补传

wireframe P12 / P12b / P12c

三态互斥：断网横幅 → 补传中 → 完成，横幅替换而非叠加。

全程非阻断：不锁屏、不弹窗、不打断录入 —— 现场不能等人。

第二部分 · 裁判长端6 个功能域

登录与身份（两个范围）

wireframe P1.6 · 与普通裁判同一平板 App

执裁范围管「本站」，管理范围管「全赛事」—— 两者是不同维度，不冲突。

普通裁判登录后直达 P2、没有管理页签；裁判长由 P1.6 进入 P7。

工作台 ·「执裁」页签

wireframe P7 / P7c（空状态）

顶栏徽标与页签角标口径不同：徽标只算争议，页签算全部待办（争议 + 改分）。

空状态的前提是「有赛台、无场次」，不是「无赛台」—— 登录本身已要求预绑赛台。

裁判长工作台页签（管理待办）

wireframe P7b

两级角标：页签管「哪里有活」，行内管「哪一项有活」，相加必须等于页签数字。

③ 的「阻断」对应发布门（P11 的红项），与①②的件数不是同一个计量单位，所以只给词。

争议裁定（裁定台）

wireframe P8 / P8a / P8b / P8c / P8f / P8d / P8e

授权改分只是生成改分单、转 P9，仍须再授权一次才生效；取消资格＝本轮成绩作废，与红牌无关。

裁定后排名按各自绑定版本自动重算；已发布赛项会常驻「待重发」提示。

改分审批

wireframe P9 / P9b

允许自批（现场常只有一位裁判长），但必须看得见、查得到：标「自批」并单独告警。

改分不改审批留痕：谁申请、谁批准、改前改后、为什么，全部可追溯。

发布前确认与发布回流

wireframe P11 / P13

裁判长只做确认（完整性校验），实际发布由工作人员在后台执行 —— 职责分离。

不做撤销发布，改分后改用常驻重发提示，避免「现场屏 ≠ 后台真值」。

第三部分 · 后台管理10 个功能域

总览（赛事全局）

后台 dash · 当前赛事 = 一套数据空间

数据按赛事隔离：切赛事＝整套数据切换，不是筛选。

赛事管理

后台 contests

归档案是快照：解档后编辑的是线上副本，再归档会生成新快照，追溯始终读归档时刻。

赛项规则不再存赛事副本，赛事只引用全局模板，避免每办一场就分叉一套规则。

赛项与规则（全局模板）

后台 events · 三赛项统一模板

浏览器里持久化的旧模板会盖掉新代码 —— 模板 key 带版本号，改结构必须 +1。

组别空数组要有兜底三档（JS 里空数组是真值，`||` 兜底会失效）。

赛台与赛程

后台 seats · 支持多天

多天赛程按日期分组显示；单天赛事不显示外层日期头，与旧版一致。

场次必须落轮次：1 轮赛项的下午场次仍是第 1 轮，按时段现推会丢队。

队伍与报名

后台 teams / import

两个导入入口已合并为一个：按表头是否含「赛项」列自动判断 WRC 还是批量。

不做清空重建：已有成绩的队伍退赛用标记，不用删。

裁判与排班

后台 referees / duty

导出 Excel 解决现场手抄码：姓名 / 手机 / 身份 / 裁判码 / 预绑 / 激活状态一表带走。

排班是整体替换式写入（「这份名单长这样」），不是逐条增删。

裁判打分（后台代录） 后续迭代

后台 score · 本期「后续迭代」置灰

后台代录与裁判端同一套口径与校验：谁录都一样，审计里能看清是谁录的。

实时榜单与比赛结果总览

后台 rank / crossrank

明细逐项之和必须等于榜单总分 —— 差额来自时间奖励与判罚扣分，要单列展示。

取消资格整行剔除、红牌保留名次 0，两者在榜上表现不同。

公示与发布

后台 publish / dq

现场大屏与实时直播已砍，只保留公示页 —— 公示页与榜单同源，避免两份数。

申报单位 / 选手信息可脱敏；作废队名次留空、名额不留。

留底证据库与合规 后续迭代

后台 evidence / roles / audit · 本期「后续迭代」置灰

这两域本期置灰，靠流程约束；补齐前「权限」只是界面软引导。

第四部分 · 跨端主链路1 个功能域

从建赛到公示：7 步交接

后台 → 裁判端 → 裁判长端 → 后台

每步的交接物：规则模板 → 归台名单 → 裁判码 → 已签成绩 → 裁定/审批单 → 发布单元 → 公示表。

断网不影响 ④：成绩先落本机，联网补传后才算进发布门。

第五部分 · 贯穿机制1 个功能域

贯穿三端的六条口径

适用于全部 44 页线框与后台 14 个入口

取消资格＝成绩作废、整行不进榜单；红牌＝当场取消比赛资格、成绩保留、名次 0。

版本复现：成绩必须按「打分时刻的规则版本」重算，否则页面上的旧值本身不可信。

发布键不在裁判长手里：裁判长只做完整性确认，发布与重发由工作人员执行。
