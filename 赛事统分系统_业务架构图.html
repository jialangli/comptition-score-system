产品决策（2026-09-17）：恢复「现场大屏」。依据 9/17 需求评审会结论，大屏重新纳入范围（推翻 2026-09-03「现场大屏与实时直播不做」的决策）。规格要点：按赛项分屏、同赛项下不同组别同页分区；展示全部队伍排名（非仅前几名）；每屏 10 条、停留 1 分钟后分页轮播；选手姓名脱敏（如「张*」），队名与学校保留；运营侧提供「置顶 / 锁定本场」开关；刷新延迟 ≤ 5 秒。官网公示页仍为对外出口，与大屏同源同步。
产品决策（2026-09-17，同日补充）：取消「颁奖 PPT 自动生成」。系统只负责产出结构化、可导出的成绩数据（CSV / 打印视图），幻灯片由人工基于导出数据制作，不在系统内自动生成。同步明确：现场大屏在「实时榜单」之外，新增「赛后成绩公示表」模式——赛事结束后展示官方公示成绩（名次 / 队伍 / 学校 / 总分 / 奖项），与「公示与导出」页同源、同脱敏开关，保证大屏与对外公示页逐行一致；未发布时提示「草稿预览」。

三条业务铁律（贯穿全流程）：① 队伍数据只产生于 WRC 报名环节（外部唯一源头），本系统负责接入、核对与锁定，下游全部只读消费；② 任何成绩可追溯到"谁在什么时间打了什么分"（全链路审计）；③ 公示是成绩的"锁定点"——公示前可仲裁修改，公示后即冻结，争议走线下申诉通道。

三、业务能力地图（Capability Map）

🏁 赛前能力域

  • 赛事配置赛项 / 组别 / 赛制 / 截止时间 / 打分规则模板
  • WRC 报名对接报名在 WRC 官网（外部），本系统承接导出 Excel
  • 队伍导入WRC Excel 导入，列映射 + Diff 合并式入库
  • 名单核对导入后人工核对（组别/学校），通过才锁定
  • 队伍编号本系统按赛项×组别分段重发号（WRC编号仅对账），退赛软删除
  • 赛程编排分组、轮次、场地、候场队列

⚡ 赛中能力域

  • 队伍轮转调度自动叫号切换，裁判端零操作
  • 多赛项打分规则模板驱动：任务题卡 + 控件语义匹配
  • 计时与时间奖励计时器自动映射梯度加分
  • 犯规与扣分结构化犯规记录，提交前红字确认
  • 成绩实时汇总两轮最佳、重复打分 ⚠ 检测
  • 仲裁工作台争议成绩裁决、修改留痕

🏆 赛后能力域

  • 排名计算按组别排名、并列规则可配置
  • 奖项映射一/二/三等奖自动划分、冠军特写
  • 公示发布按"赛项×组别"分批发布，CSV/Excel
  • 现场大屏（实时榜单）赛中：按赛项分屏、组别分区；全部队伍排名分页轮播（每屏 10 条 / 停留 1 分钟），姓名脱敏，运营可置顶锁定本场
  • 成绩公示大屏赛后：展示官方公示成绩表（名次 / 队伍 / 学校 / 总分 / 奖项），与「公示与导出」页同源、同脱敏开关；未发布时提示"草稿预览"
  • 颁奖支撑提供最终名次 / 奖项数据；颁奖 PPT 由人工基于导出数据制作（系统不自动生成）
  • 数据归档赛季数据沉淀、导出复盘

🧩 公共支撑域（跨阶段复用）

  • 账号与权限教练 / 裁判 / 记分员（裁判长）/ 主办方四角色 RBAC；裁判长可兼任现场执裁
  • 消息通知短信 / 邮件 / 微信模板消息
  • 审计日志导入、打分、修改、发布全留痕
  • 导出引擎统一产物：Excel / CSV / 大屏页
  • 规则配置中心打分规则、并列规则、奖项规则
  • 合规与脱敏未成年人信息加密、导出与大屏脱敏
能力复用关系："规则配置中心"同时驱动赛前打分模板和赛中题卡渲染；"导出引擎"同时服务公示表、大屏和归档报表；"审计日志"覆盖三个阶段的所有写操作。公共支撑域是让三个阶段共用一个系统（而非三套工具）的关键。

业务对象产生环节状态关键点对下游的约束
报名名单赛前·WRC导出导入人工核对通过后才可锁定未核对的队伍不得进入打分系统
队伍赛前·导入编号锁定后不可改，退赛只软删除历史成绩永不悬空
打分记录赛中·裁判提交需选手签名确认提交后裁判不可单方面修改，只能走仲裁
成绩赛中·汇总同队同轮重复 → ⚠待仲裁待仲裁成绩不参与排名计算
排名赛中/后·计算实时可见、公示版冻结公示版与实时版分离，避免争议
公示产物赛后·发布发布即锁定该轮全部成绩发布后修改必须"解锁→改→重发"三步留痕
