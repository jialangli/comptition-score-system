一、总体分层架构

数据源层
📋 WRC 官网导出报名 Excel（主通道） 队伍在 WRC 官网报名 → 主办方后台导出报名表
含：队伍编号 / 名称 / 学校 / 教练 / 组别 ✅ 主数据源pandas + openpyxl 解析
☁️ 赛事后台 API 直连（远期可选） 若后续与 WRC / BrainAI 后台打通接口
可免落 Excel 直接拉取，免人工导出 REST 拉取 · 未打通前不启用
✍️ Web 手动录入 现场补录 / 少量临时队伍
表单 + 编号唯一性即时校验 管理端表单
⬇结构化队伍数据流
导入服务层
① 解析器 Parser Excel 列映射 / API 字段映射 / 表单字段
统一输出中间格式 三源归一
② 校验器 Validator 编号唯一 硬校验 · 编号正则 ^\d+$
组别/赛项合法性 · 必填完整 失败即拦截
③ Diff 对比器 与库内现有队伍比对：
新增 N / 更新 M / 跳过 K / 冲突 C 合并式 ≠ 覆盖式
④ 预览确认 Preview 四色变更清单 + 首行示例预览
人工确认后才入库 防导错列
⑤ 入库 Commit 事务写入 + upsert
+ import_logs 审计留痕 可回滚
⬇唯一真相源 Single Source of Truth
数据层
teams 队伍主表 队伍编号 / 名称 / 学校 / 教练 / 组别 / 赛项 / 状态 打分系统唯一队伍数据源
import_logs 导入审计表 每次导入：来源 / 时间 / 操作人 / 变更明细 / 结果 争议追溯依据
⬇只读拉取 · 订阅变更（新增/更新队伍实时下发）
消费层
👨‍⚖️ 裁判端（平板） P2 当前比赛页队伍队列
自动轮转 · 无需手选
📊 排序 / 排名服务 按组别计算两轮最佳成绩排名
📢 公示表生成 按"赛项×组别"发布 CSV / Excel
🏆 颁奖 PPT 生成 python-pptx 按排名自动生成
架构要点（源自 fllscoring 源码调研的教训）：
① 队伍数据是打分系统的唯一真相源，裁判端/排名/公示/PPT 全部只读消费，不产生队伍数据；  ② 导入采用合并式 + Diff 预览，而非 fllscoring 的"清空重建"（覆盖会切断已关联的成绩数据）；  ③ fllscoring 浏览器版的服务端只有 GET 路由导致保存静默失败——本架构导入走独立 POST 接口 + 事务，杜绝该缺陷。

二、导入流程（以 Excel 为例，含异常分支）

1
选择来源 上传 WRC 导出的报名 Excel / 手动表单
2
解析 + 列映射 识别表头，用户确认"哪列是编号/名称/组别"，首行示例预览（抄 fllscoring 的防呆设计）
3
字段校验 编号正则 · 唯一性 · 组别合法
失败 → 标红行内提示，可修正后重试
4
Diff 对比 生成四色变更清单：
🟢新增 / 🟡更新 / ⚪跳过 / 🔴冲突
5
人工确认 勾选要应用的变更（可全选/部分选）
冲突项必须逐条裁决
6
事务入库 upsert 写 teams 表
+ 写 import_logs
失败整体回滚
7
广播变更 WebSocket 推送 → 裁判端队伍队列即时更新
Diff 结果判定条件处理策略默认
🟢 新增库中不存在该队伍编号插入新纪录勾选
🟡 更新编号相同，名称/学校/教练等字段有变化显示字段级 diff（旧值 → 新值），按字段确认勾选
⚪ 跳过编号相同且字段完全一致不产生任何写入置灰
🔴 冲突同一编号在导入文件中出现多次，或组别与已关联成绩的赛项不符必须人工裁决：取哪条 / 手改；未裁决不能提交强制拦截

三、数据模型

teams 队伍主表

字段类型说明
team_idINT PK自增主键
team_numberVARCHAR UK队伍编号（唯一，正则校验）
team_nameVARCHAR队伍名称
schoolVARCHAR学校 / 机构
coachVARCHAR教练姓名
event_codeVARCHAR赛项：BCSTAR / MARS / FUTURE
group_codeVARCHAR组别：小学组 / 初中组 / 高中组
statusVARCHARactive / withdrawn（退赛）
sourceVARCHARexcel / api / manual
created_at / updated_atDATETIME时间戳

import_logs 导入审计表

字段类型说明
log_idINT PK自增主键
sourceVARCHARexcel / api / manual
operatorVARCHAR操作人（记分员账号）
summaryJSON{insert:N, update:M, skip:K, conflict:C}
detailJSON逐条变更明细（含旧值/新值）
statusVARCHARsuccess / rolled_back
created_atDATETIME导入时间
💡 关联关系：scores 成绩表.team_id → teams.team_id（外键）。 队伍"退赛"用 status 软删除，不做物理删除——已有成绩的历史队伍必须保留，这是与 fllscoring 覆盖式导入的本质区别。
